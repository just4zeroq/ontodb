# 已知边界与技术债（全仓汇总）

> 本文汇总源码中"文档/设计宣称 vs 实际实现"的差异。目的是让架构文档与读者对系统成熟度有准确预期，**避免把规划能力误当已实现能力**。
> 各条目均在对应模块文档中有详细展开。基于 v0.6.2 源码。

---

## 1. 全局判断

OntoDB 的**核心引擎是扎实可用的**：

- ✅ LSM 存储（WAL/MemTable/SSTable/Compaction/MVCC/索引/HNSW）
- ✅ OWL 2 RL 本体推理（7 规则 + 不动点 + 四种推理模式）
- ✅ 查询执行（Parser/Planner/Executor + OntoQL/SPARQL + 类层次扩展）
- ✅ 图 CRUD / 遍历 / 核心图算法
- ✅ 多协议服务（HTTP/TCP/PGWire/MySQLWire）+ 安全合规套件

而 README "33 项核心技术" 中的**部分能力属于规划、原型或骨架**：

| 能力 | 状态 | 对应模块文档 |
|------|------|--------------|
| 联邦查询 / 语义缓存 / 融合优化器 | 独立组件，未接入执行路径 | 04 |
| CDC 变更捕获 | 框架完整但**未接线** | 07 |
| 分层存储 / TSM | 原型，未接入主引擎 | 02 |
| 插件系统 | 协议骨架，无调用方 | 06 |
| 分布式图 / GNN / 流式图计算 | 模拟 / 演示 / 未接线 | 05 |
| 边缘上报接收端 | 客户端有，服务端无路由 | 09 |
| 本体驱动规则引擎（企业版） | 路线图 | 10 |
| Raft / Sharding / 加密 / 脱敏 | 私有 crate，开源不可见 | 07 |

## 2. 按类别汇总

### 2.1 "已实现但未接线"（代码在，未接入主链）

- **联邦查询 / 语义缓存 / 融合优化器**（onto-query）：全仓除自身文件外引用为 0，未接入 `QueryExecutor`。
- **CDC**（onto-server）：CLI 参数 `cdc_enabled` 定义未读取，无 CdcManager 调用。
- **MemoryManager**（onto-storage）：构造但未接入写入路径，方法无调用点。
- **TieredStorage / TSM**（onto-storage）：未导出、未集成。
- **增量缓存 API**（onto-graph）：`record_edge_change` 只在示例使用。
- **onto-plugin**：无任何下游依赖。

### 2.2 "声明与实现有差异"

- **向量增量持久化**：模块仍在但已废弃，改为"文档为真值源 + 全量快照"（`engine.rs:556-566`）。
- **MemTable**：`lib.rs` 注释称 skip list，实为 BTreeMap。
- **R*tree**：注释称 forced reinsertion + 最小重叠分裂，实为简单二分分裂。
- **DTW**：注释称 O(n)，实为带 band 的 O(n·w)。
- **OntoQL**：文档称 MATCH 图模式，解析器无此分支；自述 Phase 1 而执行器已 Phase 24+。
- **QueryConfig 默认值**：注释 30s/256MB，实际 3600s/4GB。
- **插件依赖拓扑排序**：文档声称自动排序，实现只检查是否已注册。
- **StreamingPageRank**：自承不跟踪入边，非真正增量 PageRank。

### 2.3 "服务端 stub / 静态响应"

- 社区版企业端点统一返回 403 stub（`http.rs:943-962`）。
- `/api/graph/distributed/status` 返回静态 `"mode":"standalone"`。
- `/api/graph/streaming/event` 解析事件后丢弃，`/stats` 静态上报。
- `/api/edge/report` 接收端缺失。

### 2.4 "安全相关注意点"

- PG/MySQL wire 无查询指标/审计/限流/TLS；PG 明确拒绝 SSL。
- 游标签名只解析 offset 不校验 HMAC，密钥硬编码。
- CLI 的 TLS TODO、AUTH 占位；TCP 协议未处理 AUTH。
- MySQL 认证忽略 challenge，非标准 mysql_native_password 握手。

### 2.5 "领域耦合 / 工程遗留"

- `onto-graph::relation_table_name()` 硬编码 `sembio` 命名空间（生物医学领域假设）。
- v1/v2 索引双格式（`__idx__` / `__idx2__`）并存。
- `engine.rs.bak` 遗留文件；`bug.md` 记录堆损坏残留疑点（当前哨兵校验为修复）。
- 管理 API 路由语法 `:key` 与 `{key}` 混用。
- 两套推理器并存（onto-ontology 本体推理 / onto-graph 图三元组推理）。

## 3. 使用建议

1. **架构决策时**：以本汇总为边界清单，涉及上述能力的方案需评估"是否已接线"，必要时自行补齐。
2. **二次开发时**：优先复用"已实现且已接线"的核心能力；对"已实现未接线"组件（如 CDC、语义缓存）可在其基础上补齐集成层。
3. **对外宣称时**：区分社区版实际能力与"33 项核心技术"中的路线图能力，尤其 CDC、分布式、企业安全特性。
4. **版本演进**：本文基于 v0.6.2，后续版本如修复上述边界，应同步更新对应模块文档与本文。
